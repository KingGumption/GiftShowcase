2. Creator workflow

Existing overlay families

  1. Open Gift Carousel, Reward Rows, Side Gifts, Goal Bar or Top Likers. Open a saved design, or start a new one.
  2. In Style → Compact graphics, choose the presentation. The source dimensions are shown on each choice. Choosing a graphic creates an unpublished edit; it does not immediately change the live source.
  3. Edit cards, trigger type, gift selection, text and sounds in the existing inspector. Clicking a gift in the preview selects and scrolls to its relevant editor card. There is no persistent selection outline in the output preview; keyboard focus remains visible.
  4. Choose a colour look or transparent look. Use Original layout to exit the compact renderer, retaining the underlying native settings.
  5. Save. Direct link continues to refer to the same design. The source follows saved changes.
  6. Use Add to canvas or Direct link. New canvas placements use the compact dimensions. Existing canvas layers retain their chosen position/size; review their scale in Canvas Designer after changing a graphic.
  7. Open Live graphics to manage a saved compact design during the live.

New live graphics

  1. Open Live graphics from Studio. Choose Community combo, Crown raid, Pick our path or One more thing.
  2. Name the design, choose rules and style, and check the muted preview. Sample event affects only the preview.
  3. For a vote, choose two different gifts for A and B; choose quantity or coin weighting. For a raid, choose coins or fixed damage, maximum HP and an optional gift ID filter. For quests, add up to eight labelled steps with event and target. Gift selectors show images and coin icons, support name/ID/coin-range searches and include account creator gifts. Use the advanced ID field only when needed.
  4. Choose a bundled or already uploaded event sound, or No sound. Upload management remains in Studio’s sound library. Set a volume.
  5. Save, then copy the Direct link or add to a canvas. Add the URL as a Browser Source in the streaming software and use the stated width and height.
  6. Keep TikFinity’s Event API active on the streaming computer. Keep at least one source open. Open the live panel before beginning and click Start, confirming the new session.

Drafts and recovery

Revert to last save is beside Save in the editor toolbar, enabled only for unpublished changes to a saved design. It fetches the latest server save. It does not change another overlay’s draft or rotate source links. In Live graphics, the equivalent control restores saved graphic settings; reset of live totals is a separate command. New unsaved designs must be named and saved before a permanent source link can be issued.

Before going live: verify the source loads, check audio routing in the streaming software, confirm gift IDs, start a fresh session, and verify the panel shows Running. During the live: use Pause before changing game/scene or correcting a value; use Hide when the graphic obstructs content. After the live: End the round, hide sources as appropriate and save any desired appearance edits. Never use sample preview URLs as production source URLs.

Multiple instances of the same saved compact design share one session. A design used twice on a canvas is not two separate challenges. Duplicate the design if you want independent totals. For sound, use a single audible instance per design to avoid duplicated audio from two rendered sources.

4. Style and colour system

  • Default: restore the original family appearance and exit an optional compact presentation. Original layout separately restores the native renderer without resetting colours.
  • Clean, Soft glass, Arcade, Sunset: palette/surface choices in the existing Style card. They keep content and sound mappings.
  • No background: existing surface-free option. New options are Clear · Pearl, Clear · Mint, Clear · Gold and Clear · Ice. These retain art, text and progress marks without card/shell backgrounds.
  • Top Likers colours: milestone card and milestone text remain independent. New first-place highlight and first-place text fields control the leader’s accent and copy. Custom leader accents also tint the leader sparkle artwork. Legacy designs retain their original gold until the custom colour is saved.
  • Live graphics: Sea glass or any of the four transparent looks, plus direct text/accent colour controls. These are separate from rule settings.
  • Motion: short icon feedback on hover/keyboard focus, no continuous interface icon loops. New gift artwork uses a brief nudge; reduced-motion and disabled-animation preferences suppress it.

5. Implementation architecture

graphics-core.js owns the shared definitions, dimensions, configuration accessor, safe option normalization, event normalization and deterministic state transitions. It is used by the browser and Worker. index-graphic.html, graphics-renderer.js and its stylesheet implement the compact renderer. studio-graphics.js adds opt-in presets to the existing editor. index-live-graphics.html and live-graphics-studio.js provide live management and the new-design form.

graphics-live.mjs implements the Durable Object state adapter. Existing DockHub instances keyed by design:<id> serialize state changes using a concurrency gate. The Worker validates account ownership or source membership before forwarding a request. New commands publish a state notification through the existing source update channel; public renderers also refresh state on a bounded 1.5-second fallback.

Configuration compatibility

The opt-in marker is graphic inside the relevant family object: carouselTheme, rowsTheme, sideGifts, goalBar or topLikers. Without a recognized marker, the old renderer and dimensions remain in use. The new four live types use a compatible Goal-family storage record internally, distinguished by their marker and shown in Live graphics rather than the ordinary Goal Bar design list. No schema migration or rewrite of existing designs is needed.

{
  "goalBar": {
    "text": "#ffffff", "accent": "#add8c8",
    "graphic": {
      "variant": "vote", "label": "Where next?", "duration": 60,
      "aName": "City lights", "aGift": "ENTER_GIFT_ID_A",
      "bName": "Ocean route", "bGift": "ENTER_GIFT_ID_B",
      "weight": "gifts", "hold": 4, "sound": "", "volume": 85
    }
  }
}

Colours, content and mappings remain in the existing family schema. Existing form synchronization preserves an optional marker. Public source and canvas sizing consult the shared definitions. Graphic preview URLs carry full configuration; old compact URL codecs remain compatible. Source tokens remain unchanged across saves, Revert and live commands.

Session model

A session has epoch, phase (idle/running/paused/completed), visibility, timestamps, totals, vote counts, HP, quest position, ranked people, current reaction and a bounded queue. Saved rules are snapshotted at Start/Reset. Saving a new threshold during a running session does not silently alter that session. Appearance changes can still update the source. Rule snapshots and transient state are stored separately in bounded chunks; session snapshots are not rewritten for every event.

Transient live state has a 24-hour lifetime. It is not a permanent viewer history. Expiry returns the renderer to a fresh default session; creators should Start a fresh session before each show. Deleting the design or account purges its state through the existing deletion broadcast. Deleting or rotating a source capability prevents further reads/event submission through that URL.

Source links are bearer capabilities and must stay private. A source capability can submit event data for an included compact design. It cannot Start, Reset, adjust values, save a design, edit account data or access unrelated designs. This is appropriate for a private creator tool; it is not an anti-cheat or financially authoritative voting system. A leaked source link should be replaced. Event coin values originate from the local TikFinity message, not a signed TikTok transaction receipt.

7. Event correctness, queues and privacy

  • Normalize gift, like, follow and share events. Require a stable message/event ID. Unsupported messages and messages without an ID are ignored instead of guessing and double-counting.
  • For repeatable gift streaks, wait for the final repeatEnd event and count the final repeat quantity once. An in-progress streak does not award repeated damage/votes.
  • Deduplicate by normalized event ID across all instances of a saved design. Keep at most 1,000 recent IDs within a two-minute window. After that retention window a delayed replay may be accepted; this is not a permanent audit ledger.
  • Batch up to 40 events per request, bounded to 200 events per design per second. Browser batches are bounded; disconnected transport is not an unbounded durable queue. Network outages can lose events; pause and reconcile via manual correction if needed.
  • A new session epoch prevents already queued old-session batches from affecting reset totals. Paused events are ignored. Unknown gift coin values contribute zero in coin-weighted modes; choose fixed damage or quantity weighting when coin data is unavailable.
  • Visual card reactions have a maximum queue of 12. Overflow visual reactions are dropped; boss, combo and vote counting occur separately from this visual queue. Clear reactions does not alter counted totals.
  • Keep at most 100 ranked/participating viewers. Usernames and avatar URLs are transient presentation data; do not log full payloads or source tokens. Source state is scoped to its private capability.
  • Render all names/labels through text escaping. Accept only safe image/audio URL protocols. Apply validated hex colours. UI samples never call the live event ingestion endpoint.

Payload compatibility follows TikFinity’s Event API documentation and the upstream connector’s payload migration reference and gift-event reference. Both flattened and nested common/user/gift fields are accepted; final streak handling supports boolean and numeric completion flags.

8. Required verification

  1. Unit-test all fourteen definitions and native sizes, matching rules, final streak handling, duplicate suppression, stale epochs, paused deadlines, completion, bounds, queue overflow and rule snapshots.
  2. API-test owner isolation, unrelated source membership, malformed bodies, invalid commands, rate bounds, concurrent duplicate events, revocation and deletion cleanup.
  3. Browser-test every compact preset: choose, save, reload, Direct link, add to canvas and Original layout. Test transparent colours and first-place/milestone colours in both raw and compact configurations.
  4. Run live controls against multiple sources of the same design. Start, pause, resume, adjust, hide/show, clear, end and reset must agree across instances. Reload must read authoritative state.
  5. Verify sample events never mutate production sessions. Test all four new types with empty, active, paused and completed states.
  6. Check Layout and preview alignment at desktop and phone widths, unique icons, reduced motion, keyboard navigation, accessible fields and readable long labels.
  7. Run the existing complete release gate. Retain source backups and hashes, deploy directly with Wrangler, verify live assets and disposable-account flows, then delete verification data.

Browser tests do not prove identical audio/network permissions in every streaming application. Validate the actual Browser Source and TikFinity connection in the software used for the live show.
