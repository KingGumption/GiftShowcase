Email & access operations

The site supports an invitation-only workflow and branded transactional email. Delivery stays disabled until a verified sender and provider key are configured. Gmail can receive request notifications; its password is not needed.

Free email provider

Resend’s free transactional plan provides 3,000 emails per month with a 100-per-day limit. The application reserves a lower allowance of 90/day and 2,900/month and never upgrades a plan or enables paid overages. Provider plan rules can change; check the linked plan before enabling sending.

Cloudflare’s arbitrary-recipient sending requires Workers Paid, so it is not used as the free option here. Receiving notifications in a Gmail inbox does not require a Gmail integration.

One-time sender setup

  1. Create a free Resend account. Add your domain and verify the exact SPF/DKIM records shown by Resend. Do not replace existing domain mail records with guessed values. Use a sending subdomain if the main domain already handles mail.
  2. Create an API key restricted to sending for the verified domain. Store it as the Cloudflare Worker secret RESEND_API_KEY. Do not paste it into website forms or commit it to GitHub.
  3. Set ACCOUNT_EMAIL_FROM to the verified branded sender, for example King Gumption Studio <studio@kinggumption.com>. Use the exact address permitted by the verified domain.
  4. Set INVITE_NOTIFY_EMAIL to your chosen notification inbox. This is also the Reply-To address. It is configured privately in the deployed Worker, not published in the repository.
  5. Set ACCOUNT_EMAIL_ENABLED to true in the deployment configuration and deploy. The admin Email panel should now report delivery configured.
  6. In Administration → Email, send one delivery check to the configured notification inbox. Confirm inbox/spam delivery and verify a real invitation and recovery email before relying on the process. Leave click tracking off for authentication links.

Example commands, run from the Cloudflare project directory with Wrangler authenticated:

wrangler secret put RESEND_API_KEY
wrangler secret put ACCOUNT_EMAIL_FROM
wrangler secret put INVITE_NOTIFY_EMAIL

Wrangler prompts for values without placing them in source control. Setting the API key alone does not turn delivery on: the feature flag and verified sender are required too.

Invitation process

  1. A creator submits name, email, channel and a short request at Request an invitation. A privacy acknowledgement is required.
  2. The request enters Pending. When mail is configured, the creator receives an acknowledgement and the notification inbox receives a branded review email.
  3. An administrator approves or declines. Approval creates an address-bound, single-use invitation that expires after seven days. The creator chooses a password of at least 15 characters. The server rejects registration without an approved invitation.
  4. If sending is not configured or fails, approval still records the decision and the admin can copy the private invitation link. The interface does not claim it was sent. Creating a fresh invitation revokes older unused links.
  5. After successful account creation, the invitation is consumed atomically. The new creator receives the welcome template if email is available. Existing members continue to sign in without a new invitation.

Account email process

Password-reset requests use a generic response for known and unknown addresses. Reset links expire in 20 minutes and are single-use; changing the password invalidates previous sessions and action links. Email changes require the current password and confirmation at the new address, with a 30-minute expiry. The previous address remains active until confirmation.

The public interface only offers email recovery when sending is configured. Do not promise delivery while the Email panel says setup incomplete. Failed email attempts are visible in the admin delivery log; tokens and message bodies are not logged there.

User administration

Administration is enforced by the API, not just by hiding a navigation link. Administrators can search users, review design/canvas/session counts, suspend or restore access, sign out sessions, and delete an account and its hosted data. User actions require typing the target email and a reason. Administrator accounts are protected from these actions.

Suspension revokes sign-in sessions and stops published sources while retaining designs and media. Restoring access permits sign-in again; refresh a stopped Browser Source to reconnect. Signing out sessions alone keeps published source links working. Deletion is permanent and removes designs, links and hosted uploads through the existing account-cleanup path.

Privacy and retention

Only authorised admins can see access requests, user emails and delivery/audit logs. Passwords, API keys, session tokens and invitation/recovery links are excluded from these logs. Pending access requests are retained for review; reviewed requests are removed after 180 days, delivery/audit logs after 90 days, and expired invitation records daily. Existing user-owned design data remains subject to the account export/deletion controls.

Templates available for review

Request acknowledgement · New request notification · Approved invitation · Decline · Welcome · Password reset · Email confirmation · Password-change notice · Email-change security notice · Delivery check. Each includes a plain-text version, an accessible branded HTML layout and canonical site links. Live template previews are available to administrators.
